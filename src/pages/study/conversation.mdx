- **Offline**, the installed model reads every scheduling request, not only unclear ones.
- **During a live call**, a confident rule result is trusted immediately so the student isn't kept waiting.
- Non-scheduling intents (queries, updates, deletes, notes, call replies) **never** go to the model's title extractor.

### The intent types

| Group | Intents |
|---|---|
| Create | `create_task`, `create_time_block`, `create_reminder`, `create_note`, `create_alarm` |
| Update | `update_task`, `update_time_block`, `update_note`, `update_alarm`, `toggle_alarm`, `reschedule` |
| Delete | `delete_task`, `delete_time_block`, `delete_note`, `delete_alarm` |
| Reminder replies | `acknowledge`, `snooze` |
| Read only | `query_schedule`, `query_notes`, `list_alarms` |
| Conversation | `chat`, `out_of_scope` |

An intent carries **slots**: `title`, `date`, `time`, `endTime`, `durationMinutes`, `category`, `details`, `snoozeMinutes`, `confidence`, and `source`.

## Step 5 in detail: the three routes

| Route | Writes? | Which intents | Notes |
|---|---|---|---|
| **reviewed_mutation** | Only after Confirm | All create, update, and delete intents, plus acknowledge and snooze | Low-risk ones apply immediately with Undo |
| **read_only** | Never | `query_schedule`, `query_notes`, `list_alarms` | Answered from SQLite |
| **conversation** | Never | `chat`, `out_of_scope` | DeepSeek or a local reply |
| *call_context_immediate* | Yes | `acknowledge`, `snooze` | **Only while a reminder call is ringing**, using that call's identity |

<Card title="Exhaustive by design">
  The route table is a typed map in code (<code>INTENT_ROUTES</code>). Adding a new intent <strong>fails to compile</strong> until someone chooses its route, so no intent can accidentally write without review. An unknown value falls back to <em>conversation</em>, which never writes.
</Card>

## Review cards: the lifecycle

<FlowChart
  label="Review card lifecycle"
  steps={[

      { title: 'Confirm', text: 'Saved in one transaction + operation receipt', kind: 'end', edge: 'confirm' },
    ],
  ]}
/>

- **Revision checks:** confirming an outdated version of a card is refused, so you always save what you saw.
- **Receipts:** every confirmed operation is recorded in `assistant_operation_receipts`.
- **Low-risk actions** skip the card and offer **Undo**: completing a task, acknowledging or snoozing a reminder, and pinning or re-categorizing a note.
- **Multi-action:** "Add my quiz on Monday and a study block on Sunday" becomes a batch with **Confirm All**.
- **Conflicts** are shown on the card, with free times offered as one-tap choices.
- **Deletes** are never prepared from the model's words alone.

## Conversation replies: online vs. offline

| | Offline | Online Mode |
|---|---|---|
| Small talk (hi, thanks, who made you, what can you do) | ✅ Varied local replies | ✅ DeepSeek |
| Trivia and general knowledge | ❌ "That question needs Online Mode" | ✅ DeepSeek, streamed word by word |
| Questions about your plans | ✅ From SQLite | ✅ Chat agent can look things up |
| If DeepSeek fails | n/a | Local reply, labeled *"Offline reply"* |

**Privacy rule:** the planner snapshot is sent only when the question is about the student's own plans, notes, or time. A general study question never sends the planner.

## Memory

| Item | Detail |
|---|---|
| What | Facts the student shares: preferred name, study hours ("night owl"), goals |
| Tiers | `core`, `preference`, `episodic` |
| Commands | "What do you remember about me?", "Forget that I'm a morning person", with Undo |
| Used for | Online replies, study scheduling, Morning Briefing |
| Guard | Passwords, PINs, OTPs, card numbers, and bank or GCash numbers are never saved |
| Off switch | Memory can be turned off. **Temporary Chat** saves nothing |

## Other chat features

- **Temporary Chat:** messages and memories are not saved.
- **Ask USTP mode:** a dedicated chat that goes straight to handbook Q&A (Lesson 9).
- **Quick Chat / Floating LAFINA:** the same rules in a small window over other apps.
- **Chat history sync:** chats sync with an account, up to **20 chats** per account.
