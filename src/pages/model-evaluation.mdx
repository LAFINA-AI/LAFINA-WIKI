## Task-Specific Accuracy

To ensure reliability, we evaluate the model using a "Golden Dataset" containing 50 to 100 typical voice commands. This dataset includes straightforward requests, messy inputs, and relative time expressions. The primary metric is the **Exact Match Rate** for accurately extracting JSON schedule data from these spoken inputs [cite: 347, 348, 349, 353].

## On-Device System Performance

Given the strict hardware constraints of mobile devices, system performance is continuously monitored to ensure smooth execution within a 4GB RAM footprint.

| Metric | Description | Target |
| :--- | :--- | :--- |
| **Latency** | Time to first token generation | Minimization for real-time feel |
| **Throughput** | Tokens generated per second | Fluid conversational output |
| **Memory** | Active RAM consumption during inference | Strict adherence to the 4GB RAM constraint [cite: 357, 359, 361, 362] |

LAFINA's selected architecture was chosen after extensive comparative testing against alternative methods.

## Handling Imperfect English

A key strength of the SmolLM2 implementation is its robustness in handling imperfect English. The model successfully processes misspelled words, heavy regional accents, and "Taglish" transcriptions passed down from the Whisper STT layer [cite: 370, 371].
