## The actors

| Actor | Type | Role |
|---|---|---|
| **Student** | Primary | Guest or signed-in user. Starts almost every use case |
| **Signed-in student** | Primary | Same as Student, plus account services (sync, online AI, online voice) |
| **Android OS** | Supporting | Delivers alarms and reminder alerts, and provides microphone and audio |
| **LAFINA backend** | Supporting | Account, sync, online AI and voice services |

## «include» vs. «extend»

| Relationship | Meaning | LAFINA examples |
|---|---|---|
| **«include»** | **Always** happens as part of the base use case | *Import class schedule from COR* «include» *Review and confirm extracted classes* |
| | | *Request assistant planning changes* «include» *Review and confirm proposed change* |
| | | *Ask USTP handbook questions* «include» *Retrieve supporting handbook evidence* |
| **«extend»** | **Optionally** adds to the base use case, under a condition | *Use push-to-talk voice input* «extend» *Chat and query personal plans* [when voice is selected] |

<Card title="Memory trick">
  <strong>Include = must</strong> (you can't import a COR without reviewing it). <strong>Extend = may</strong> (you can chat without voice, and voice is an optional extra). Read-only questions do <em>not</em> include a review, because nothing is written.
</Card>
