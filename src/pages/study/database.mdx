## Quick facts

| Fact | Value |
|---|---|
| Database | One SQLite file, `lafina.db`, on the phone (OP-SQLite) |
| Schema version | **28** (versioned migrations) |
| Tables | **36** application tables (with FTS5), excluding SQLite internals |
| Declared foreign keys | **3** |
| Sync entity types | **7**: profile, task, event, time_block, reminder, note, custom_category |
| Guest user ID | `local_guest_user` |

<Alert type="warning" title="Android only">
  This ERD is the <strong>Android SQLite</strong> schema. The backend's Neon PostgreSQL database is a separate schema.
</Alert>

## The three declared foreign keys

| Foreign key | On delete |
|---|---|
| `user_preferences.user_id → users.id` | Cascade |
| `messages.session_id → chat_sessions.id` | Cascade (delete a chat → its messages go too) |
| `recorded_meetings.user_id → users.id` | No cascade |

<Card title="Why are most relationships 'logical' only?">
  Planner tables point to <code>users</code> by <code>user_id</code>, but the app enforces that link in code instead of with a database foreign key. Reasons:
  <ul>
    <li>Records arrive from <strong>sync</strong> and must be applied safely even if related rows arrive in a different order.</li>
    <li>Delivery jobs and events must be able to <strong>outlive</strong> their reminder for audit and recovery.</li>
    <li><code>reminders.task</code> stores <strong>text</strong>, not a task ID, so a reminder can exist without a task.</li>
  </ul>
</Card>
